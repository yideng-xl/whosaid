# 设计：macOS 直接录音首版

日期：2026-08-12
状态：设计已确认，待实施

## 目标

让用户在 whosaid 内直接录制线上会议。首版面向开着腾讯会议的 macOS
Apple Silicon 场景，同时采集全系统声音和麦克风；停止录音后保存本地音频，
自动创建现有转写任务并进入“分人 → 转写 → 人名处理 → 导出”流程。

录音必须以系统声音为主通道。腾讯会议无法与 whosaid 共享麦克风、麦克风
权限被拒绝或设备中途失效时，系统声音仍继续录制，不能因为麦克风故障丢掉
整场会议。

## 首版范围

- 仅支持 Apple Silicon 和 macOS 13 及以上版本。
- 录制全系统声音，不限定腾讯会议进程；通知声、浏览器、音乐等系统播放声音
  也可能被录入。
- 同时尝试录制默认麦克风。
- 支持“开始录音”和“停止并开始转写”，不支持暂停、继续。
- 停止后自动保存、合成并创建转写任务，不增加二次确认。
- 同一时间只允许一场录音。
- 不录制或保存屏幕画面。
- 不做回声消除、指定应用录音、麦克风选择、实时转写、Windows 录音。

## 技术路径

采用双轨独立采集：

- `ScreenCaptureKit` 采集全系统声音，写入临时系统音轨。
- `AVAudioEngine` 采集默认麦克风，写入临时麦克风音轨。
- 两路以同一个会话开始时刻为基准记录时间戳；缓冲缺口用静音补齐。
- 停止后调用包内 FFmpeg 对齐并混合两路，输出最终 `.m4a`。
- 最终文件写稳后，通过现有 `submitJob(audioPath)` 自动创建转写任务。

不采用虚拟声卡。用户无需安装 BlackHole，也无需修改系统或腾讯会议的输出
设备。系统音频和麦克风不放在同一故障域中，麦克风失败只触发降级，不停止
系统音频采集。

## 模块边界

### macOS 原生录音桥

新增一个直接链接到 Tauri 主程序的 Objective-C++ 原生录音桥，负责：

- 检查和触发系统录音、麦克风权限；
- 启停 ScreenCaptureKit 与 AVAudioEngine；
- 写入双轨临时文件；
- 上报音源状态、音量活动、持续时长和不可恢复错误；
- 录制期间申请系统活动，避免自动休眠；
- 停止时关闭文件并返回会话清单。

原生桥通过 C ABI 接收启停命令，并用回调向 Rust 层传递 JSON 事件。Apple
框架、实时音频回调和音轨写入集中在 `native/recorder/`，不散落到现有 Rust
外壳中。原生桥必须运行在 whosaid 主进程内，使 macOS 将系统录音和麦克风
权限明确归属 `com.yideng.whosaid`，并使用主应用 `Info.plist` 中的用途说明。

协议至少包含：

- 命令：`check_permissions`、`start`、`stop`、`open_system_settings`；
- 事件：`starting`、`recording`、`source_status`、`elapsed`、`stopping`、
  `stopped`、`fatal_error`；
- 音源状态：`active`、`unavailable`、`denied`、`interrupted`；
- 停止结果：开始时间、结束时间、系统音轨路径、可选麦克风音轨路径、各路
  首帧时间和中断区间。

协议字段使用固定结构并校验路径，Rust 不拼接任意 shell 命令。原生桥上报
不可恢复错误时，Rust 协调器进入抢救保存流程。

### Tauri 录音协调器

Rust 层提供前端命令和单会话状态机：

```text
idle → requesting_permissions → starting → recording → stopping
     → mixing → ready
```

前端在拿到 `ready` 的最终路径后进入 `submitting`，调用现有任务 API；成功后回到
`idle`，失败则保留最终录音并提供重新提交。原生阶段可以进入 `failed`；`failed`
必须携带可读原因、已经保住的文件路径
以及是否可以重试混音。协调器负责：

- 防止重复开始或重复停止；
- 初始化并监控原生录音桥；
- 创建录音目录和会话临时目录；
- 调用包内 FFmpeg 合成；
- 混音成功后删除临时双轨；
- 通过 Tauri 事件向前端推送状态；
- 返回最终音频路径，由前端复用现有任务提交接口。

### 前端录音状态

前端新增独立录音状态模块和录音主面板，不把实时状态塞入转写任务对象。
录音只有在最终文件落盘并提交后才成为普通任务，避免半成品污染现有任务
持久化和队列语义。

## 文件与时间轴

录音保存在应用数据目录下的 `recordings/`：

```text
recordings/
  2026-08-12_10-30-15.m4a
  .incomplete/<session-id>/
    system.caf
    microphone.caf
    session.json
```

- 最终文件名使用本地开始时间；冲突时追加短会话编号。
- 临时轨道使用线性 PCM CAF，避免实时编码故障导致整段文件不可恢复。
- 最终文件使用 AAC-LC `.m4a`，48 kHz，满足会议语音和现有转写管线。
- `session.json` 持续记录开始时间、音轨状态和已完成阶段，应用异常退出后可以
  识别遗留录音。
- 正常混音成功后删除对应 `.incomplete` 目录。
- 混音或应用异常时保留临时轨道；首版提示文件位置和重试，不自动删除。

双轨不假定同时收到第一帧。合成时按各路第一帧相对会话开始时间补前置静音，
按中断区间补中间静音，并以系统轨长度作为最终基准。麦克风轨缺失时直接将
系统轨转码为最终文件。

## 界面与交互

任务列表顶部增加红色“开始录音”按钮。点击后进入录音主面板：

- 显示“正在录音”和持续时长；
- 分别显示“电脑声音”和“麦克风”的活动及状态；
- 麦克风不可用时显示黄色提示：“没有录到你的麦克风声音。你可以继续会议，
  系统声音不会中断。”；
- 主操作为“停止并开始转写”。

停止后在同一面板依次显示：

1. 正在保存录音；
2. 正在合成音轨；
3. 已开始转写。

任务创建后自动选中该任务并切换到现有转写视图。任务名沿用最终录音文件名。

窗口最小化不影响录音。录音期间关闭窗口或退出应用时，必须确认“停止并保存”；
不能静默退出。用户确认后执行正常停止流程，用户取消则继续录音。

## 权限

- 系统声音依赖 macOS 的屏幕与系统音频录制权限。首次点击时申请，并说明
  “whosaid 只录声音，不保存屏幕画面”。
- 系统权限未获得时不开始录音、不创建空任务，提供“打开系统设置”。若系统
  要求重启应用，界面明确说明。
- 麦克风权限单独申请。拒绝后不反复弹窗，直接进入仅系统声音模式，并允许用户
  稍后从系统设置授权。
- `Info.plist` 增加对应的系统录音和麦克风用途说明。

## 异常处理与恢复

- 麦克风启动失败、被占用、断开或中途失效：继续系统录音，上报黄色警告并在
  时间轴中记录静音区间。
- 系统音频启动失败：开始动作失败，不产生录音任务。
- 系统音频中途失败：立即停止会话，收尾已有数据；提示录音不完整及保留位置，
  不自动提交为正常转写任务。
- 磁盘不足或写入失败：立即停止并尽量关闭文件，展示具体原因和可恢复路径。
- 混音失败：保留双轨与 `session.json`，提供重试入口；不创建转写任务。
- 转写提交失败：保留最终 `.m4a`，允许从录音结果重新提交。
- 应用异常退出：下次启动扫描 `.incomplete`，提示发现未完成录音，并允许
  尝试恢复；首版不静默自动混音。
- 录制期间阻止系统自动休眠。用户主动合盖、关机或强制退出不承诺连续录音，
  但下次启动应能发现已经落盘的临时轨道。

## 测试与验收

### 自动测试

- Rust 状态机：合法流转、重复开始、重复停止、原生采集失败、混音失败、提交失败。
- 协议解析：全部命令和事件、未知字段、损坏 JSON、路径校验。
- 时间轴：两路延迟开始、短暂中断、麦克风缺失、不同长度和补静音。
- 前端：按钮状态、计时、两路状态、麦克风降级提示、停止三阶段、错误恢复。
- 集成：用生成的短音轨验证 FFmpeg 混音、最终文件可探测、随后能提交现有 API。
- 回归：已有音频拖入、分人、转写、人名统一和导出测试全部通过。

### macOS 真机验收

- 腾讯会议中使用扬声器：录到对方系统声和本人麦克风，停止后自动开始转写。
- 腾讯会议中使用耳机：仍能录到两路声音。
- 麦克风不可访问：录音不中断，对方声音完整，界面持续显示仅系统声音。
- 拒绝麦克风权限：不反复请求，系统声音录制正常。
- 拒绝系统录音权限：不创建空文件或任务，能够前往系统设置并在授权后使用。
- 连续录制两小时：最终文件可播放、无明显断裂，两路末端偏差不超过 250 ms。
- 混音失败和转写失败：分别保留双轨和最终录音。
- 录制期间最小化窗口：录音持续；退出应用：出现停止并保存确认。
- 生成物检查：只有音频、会话恢复信息和现有转写数据，不存在屏幕图像或视频。

## 不在首版解决的问题

- macOS 12 及更早系统；
- Intel Mac 和 Windows；
- 只录腾讯会议或按应用筛选系统声音；
- 暂停、继续、录音设备切换；
- 实时字幕和边录边转；
- 自动回声消除和双轨独立导出；
- 主动合盖、关机或强制结束进程时的无损连续录音。
