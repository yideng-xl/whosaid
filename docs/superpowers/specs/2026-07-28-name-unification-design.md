# 设计：人名统一替换首版

日期：2026-07-28  
状态：首版完成

## 目标

把同一人在转写中出现的同音字、错别字或不同写法，交给用户确认后一次性统一。
例如把“张山”“张三”统一成“张三”。

## 首版边界

- 本地规则只推荐候选，不自动修改文字稿。
- 候选来源包括：
  - 已由用户认领的说话人显示名；
  - 已认领全名在正文中出现的去姓称呼，如“许江辉”对应“江辉”；
  - “我是张三”“有请张三”“张老师”等明确身份介绍或称谓。
- 不扫描任意高频姓氏词。实稿证明“终端、平面、管理、安全区、应该”等
  普通词会因首字也是姓氏而大量误报；首版选择高准确率优先，漏项由手动添加补充。
- 用户可以勾选候选、填写目标名，也可以手动补充规则未识别的词。
- 一次提交可以包含多条映射，同时替换：
  - 每个 `Segment.text`；
  - `speaker_names` 中的显示名。
- 替换后立即保存 job，所有预览与 txt/srt/逐字稿导出使用新内容。

## 安全约束

- 空原词、空目标词不允许提交。
- 原词等于目标词时忽略。
- 多条映射基于同一份原文同时执行，不做连锁替换。
- 只允许修改已经完成的任务，避免与后台转写线程竞争。
- 候选规则允许漏报和误报，但不影响原稿；只有用户勾选的项目才会修改。

## 接口

- `GET /jobs/{id}` 增加 `name_candidates: [{term, count}]`。
- `POST /jobs/{id}/replace_terms`
  - body：`{"mapping": {"张山": "张三"}}`
  - response：`{"ok": true, "replaced": 3}`

## 界面

在“② 分人”完成态中，说话人重命名下方增加“人名统一替换”卡片：

- 候选原词、出现次数、是否选中、目标名；
- “添加漏掉的人名”补充手工行；
- “统一替换”提交；
- 完成后显示替换次数并刷新正文、说话人和候选。

## 验收

- 后端覆盖候选抽取、正文和显示名替换、非连锁语义、接口持久化。
- 前端覆盖候选渲染、映射组装和替换调用。
- 完整后端、前端与 Svelte 检查通过。

## 姓名库与专用词库

状态：首版已实现。

后续增加两类本地词库：

- 姓名库：保存标准姓名、常见称呼和已确认的误识别写法；
- 专用词库：保存产品名、系统名、行业术语、缩写及其标准写法。

首版界面提供“姓名”“专用词库”“其他”三个文本框，每个词之间用逗号或顿号分隔，统一
保存。后端仍按独立条目持久化，整组保存时保留未改词条的 id、别名和创建时间。每个新任务
创建时，系统把当时三个文本框里的标准写法冻结成提示词快照，交给 MLX Whisper 或
faster-whisper；任务进行中再编辑词库，不会让同一稿件前后段使用不同标准。

数据保存在应用数据目录的 `vocabulary.json`，采用带版本号的原子 JSON 写入；不会随音频
上传。提示词最多取 100 个启用条目并限制为 1000 字符，避免无边界词表稀释模型上下文。

边界：

- 姓名和专用词只保存在本机，不随音频上传；
- 上下文提示可以自动参与识别，但转写后的全文替换仍需用户确认；
- 词库不可把原稿中相似的普通词直接强制替换；
- 首版不提供文件导入导出、项目级作用范围和自动全文替换；这些能力后续单独设计。
- FluidAudio/CoreML 等后端接入时复用同一词库数据，但可按后端能力改用关键词增强，不要求
  与 Whisper 使用相同的提示方式。
